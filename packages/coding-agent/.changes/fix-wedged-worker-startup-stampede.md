- Fixed a daemon that could not start while one session worker was wedged: supervisor startup adopted every persisted worker before it would answer `daemon_hello`, and an alive-but-unresponsive worker held that up for the whole connect/list retry ladder while the supervisor kept the exclusive socket-path lock. Every other CLI gave up connecting, spawned a rival supervisor, and failed after 15s with proper-lockfile's bare `Lock file is already being held` — which spawned more rivals. Adoption now runs against a startup budget and finishes in the background, losing the socket-path lock is reported as a named error against the contended path, and the launcher waits for the winning supervisor instead of charging the rival's exit to the user's command.
